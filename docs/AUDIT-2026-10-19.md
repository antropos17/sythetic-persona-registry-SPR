# Audit and improvements — 2026-10-19

## Scope

Reviewed the public interface, Node HTTP API, SQLite writes, static-file boundary, Docker image, and GitHub workflows. Browser checks covered the desktop and narrow layouts, record lookup, notice filters, search dialog, form errors, and an in-memory report submission. This is a focused development audit, not a production penetration test or an identity-verification assessment.

## Corrected

- Malformed application evidence now returns a validation response instead of an internal error. Optional report email containing only spaces is accepted and normalized to empty.
- Host-header validation blocks a local DNS-rebinding write path while allowing the configured public origin and loopback health checks.
- A malformed hash route now falls back to the home page. The Notices route updates the document title and focus. An empty passport search now explains what to enter. A generic report no longer inherits a previously selected persona.
- Browser form limits and validation now match the API more closely, including Unicode handles. Corrupt saved application drafts are sanitized, and the form offers a clear-draft control.
- The search dialog has a visible Close button, a two-control keyboard focus loop, and an inert background while open. Form errors are associated with their fields.
- The interface identifies fictional records and proposed review stages more plainly. A green demo notice directs readers to check open risks.
- External JavaScript has fixed integrity hashes. The HTML response has a Content Security Policy. Stable asset URLs use revalidation with ETags so changed images do not remain fresh in browser caches for a day.
- The 3D passport loads the current portrait instead of preloading all eight, pauses its rendering loop while off screen or in a hidden document, and releases its WebGL context on unmount.
- CI and release smoke tests request a catalog image as well as the page and health endpoint. The release smoke container is removed even when a check fails.

## Verification

- `npm run check` and `npm test`: 7 tests passed.
- Both workflow files parsed as YAML.
- Desktop and narrow browser checks confirmed the search focus path, responsive layout, record switching, lookup result, notice filtering, and the 3D passport after scrolling away and back.
- A fictional report submitted through the browser to a separate server using an in-memory SQLite database returned a stored reference. No real contact details or production data were used.
- A bounded scan of tracked paths found only `.env.example` among secret-like filenames, and no matches for common private-key or token signatures. This does not prove the absence of every secret.

## External feedback considered

Two Reddit discussions were treated as qualitative input, not as technical authority: [design trust](https://www.reddit.com/r/UXDesign/comments/1v57key/are_you_comfortable_with_uis_made_by_ai/) and [CI cache trade-offs](https://www.reddit.com/r/devops/comments/1wtnlus/is_it_just_me_or_github_actions_is_overrated/). They reinforced a restrained interface with explicit demo boundaries and measuring CI before adding a cache. The [latest pre-audit CI run](https://github.com/antropos17/sythetic-persona-registry-SPR/actions/runs/39214123689) completed its verification job in 15 seconds, including an eight-second image build. No extra cache layer was added because this run showed no build bottleneck.

## Release boundary

This remains a demonstration. The API does not verify a face or signature, issue a real passport, assign a reviewer, send email, or expose an authenticated review workflow. A public launch still needs an evidence and consent process, authenticated operations, privacy retention and deletion rules, durable abuse controls, monitoring, and a tested database backup/restore plan. No deployment host has been selected. Browser checks here do not cover Safari or physical devices.
